Hash & Checksum Verifier

Generate cryptographic hashes for text and files offline. Private, no upload.

What is Hash & Checksum Verifier?

When you download a Linux ISO or a software release, the provider publishes a SHA-256 checksum like e3b0c442... If the file you downloaded has a different hash, it means download was corrupted or tampered. Hash verifier computes the fingerprint of text or file locally so you can compare.

This tool uses Web Crypto API SubtleCrypto.digest which is implemented in the browser in C++ and is cryptographically secure. Your files are read via FileReader API as ArrayBuffer and digested locally. Nothing is uploaded. This is critical for sensitive documents, legal files, or internal builds that you cannot send to an online checker.

How to use

  1. For text: type text, choose SHA-256, click Generate.
  2. For file: click Choose File, select file. SHA-256 appears instantly. For large files (500MB+), it may take few seconds.
  3. Compare generated hash with hash published by vendor. Must match exactly (case-insensitive).

Real example

Text: "hello" → SHA-256: 2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824

If you change one letter to "Hello" (capital H), hash becomes completely different: 185f8db32271fe25f561a6fc938b2e264306ec304eda518007d1764826381969 — this avalanche effect is why hashes detect even tiny changes.

How it works

SubtleCrypto.digest(algorithm, data) → ArrayBuffer → hex conversion. SHA-256 produces 256-bit (32 bytes, 64 hex chars). SHA-1 produces 160-bit (deprecated for security but still used for legacy checks). SHA-512 produces 512-bit. No salt, no key — deterministic fingerprint.

When to use?

  • Verify ISO downloads
  • Check backup integrity after transfer
  • Generate checksum for GitHub release
  • Learn how hashing works for passwords (though passwords need salt, not just SHA-256)

When NOT to use?

Do not use SHA-1 for security-critical signatures — it has collision weaknesses. Use SHA-256 or SHA-512. Also, hash alone does not guarantee file is safe from malware, only that it matches published hash.

Common errors

Hash mismatch: Re-download file, check if you compared correct algorithm (SHA-256 vs SHA-1).

Large file freeze: Browser may need time. Keep tab active, do not close.

FAQ

Is file uploaded? No, FileReader reads locally, digest happens locally.

Can I verify password? You can hash password, but proper password storage needs bcrypt/Argon2 with salt, not just SHA-256.

Difference between hash and checksum? Both are fingerprints, hash is cryptographic with avalanche property.
